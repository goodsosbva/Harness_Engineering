# Harness Engineering

> 에이전트가 안정적으로 일하도록 작업 환경과 진행 순서를 설계하는 실습을 모읍니다.

## 프롬프트만으로는 부족할 때

에이전트가 코드를 고치면 답변이 그럴듯한지만 볼 수 없습니다. 필요한 변경을 빠뜨리지 않았는지, 허용된 범위 안에서 움직였는지, 결과를 제대로 확인했는지도 봐야 합니다. 같은 문제가 되풀이될 때 지시를 덧붙이기 전에 작업 환경과 진행 순서를 살펴보는 이유입니다.

하네스 엔지니어링은 모델이 일하는 조건을 함께 설계하는 일입니다. 필요한 맥락과 도구를 준비하고, 역할과 순서를 정하고, 결과를 확인하는 단계까지 연결합니다. 이 저장소에는 공부하며 정리한 글과 직접 따라 해볼 실습을 담습니다.

## 다루는 것

실습은 에이전트에게 일을 맡기고 결과를 확인하는 순서로 읽을 수 있습니다.

- **작업을 맡기기 전:** 필요한 맥락은 무엇인지, 도구와 권한은 어디까지 열어야 하는지
- **작업을 진행할 때:** 역할을 나눌 필요가 있는지, 반복 절차와 다음 단계는 어떻게 이어지는지
- **작업을 마치기 전:** 결과가 실제 입력에 근거하는지, 검토가 끝나지 않으면 어떻게 멈추는지

이 과정에서 에이전트는 ‘누가 맡는가’, 스킬은 ‘어떻게 하는가’, 조율은 ‘언제 누구를 부르는가’를 설명하는 틀로 사용합니다. 정해진 공식 분류를 소개하려는 것은 아닙니다. 작업의 책임과 순서를 헷갈리지 않게 살펴보기 위한 구분입니다.
