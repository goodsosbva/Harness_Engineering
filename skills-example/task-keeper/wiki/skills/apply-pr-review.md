## 파일 구성

| 파일 | 역할 |
|---|---|
| `SKILL.md` | 반영 절차와 제약 |
| `resources/reply_templates.md` | 처리 결과별 답글 형식 (반영 / 질문 답변 / 반영 안 함 / 보류 / 종합) |

## 동작 순서

1. 대상 PR을 정하고 PR 브랜치에 있는지 확인
2. 코멘트 수집: 인라인 스레드(GraphQL, 해결 여부 포함), 리뷰 본문, 일반 코멘트
3. 지적별 분류: 반영 / 질문 답변 / 반영 안 함 / 보류. 코드를 직접 읽고 지적이 맞는지 확인
4. 반영 계획을 표로 보여주고 승인 받음
5. 코드 수정, 테스트 실행
6. 컨벤션에 맞춰 커밋하고 push
7. 답글 작성: 인라인 스레드는 스레드에 직접 답하고, 리뷰 본문과 일반 코멘트는 종합 코멘트 하나로 답함
8. (선택) 반영한 스레드만 해결 처리
9. 결과 보고

## 수집과 답글에 쓰는 API

| 대상 | 수집 | 답글 |
|---|---|---|
| 인라인 리뷰 스레드 | `gh api graphql` → `reviewThreads` | `gh api .../pulls/<n>/comments/<id>/replies` |
| 리뷰 본문 | `gh pr view --json reviews` | `gh pr comment` (종합) |
| 일반 코멘트 | `gh pr view --json comments` | `gh pr comment` (종합) |

## 안전장치

- 승인 없이 코드를 고치거나 답글을 달지 않음
- 리뷰어 의견을 무조건 따르지 않고 직접 확인함
- 반영하지 않은 것을 반영했다고, 실행하지 않은 테스트를 통과했다고 쓰지 않음
- 반영 없이 스레드를 해결 처리하지 않음
- force push는 명시적으로 요청할 때만
