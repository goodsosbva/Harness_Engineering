## 대화 흐름

1. **하네스 개념과 첫 실습 폴더** — `side/harness`에 손으로 리뷰 팀(보안·성능·스타일) 구성. 디렉터리 하나하나의 의미 설명.
2. **책 원문 해석** — static-analyzer를 "먼저 실행"하는 게 아니라 "대표 견본"으로 보여 주는 것. 저장소는 절별 스냅샷이라 ex-11-03에는 1명, ex-11-04에 4명.
3. **코드 리뷰 팀 실전** — `claude --add-dir /d/common_tester`(세션 안에서는 `/add-dir`)로 실제 프로젝트 리뷰. haiku 담당의 얕은 보고서를 메인 세션이 걸러냄. 세션 중 폴더를 옮기자 에이전트가 정식 로드되지 않아 Write 금지가 무시된 사건.
4. **풀스택 구현 팀** — 8인, Phase 0~4, 패턴 4개(계층적 위임·팬아웃·파이프라인·생성-검증). fullstack_function 폴더에 직접 쌓는 가이드.
5. **verifier 판정 기준 수정** — "구현이 안 맞으면 구현을 고쳐야지" → FIX 기본, REDO는 설계 모순·누락일 때만.
6. **레거시 마이그레이션 팀** — 3,500개 파일, 단일 에이전트·고정 팬아웃의 실패, 감독자 패턴. 저장소엔 dependency-mapper만 있어 나머지 팀원 직접 설계.
7. **도구 확인** — 이 버전에서 `/agents` 마법사 제거. `@` 자동완성으로 `(agent)` 확인, `claude plugin validate .claude/agents`로 파일 검사.

## 핵심 교훈

- 하네스는 Claude의 실력을 올리는 게 아니라 **순서·권한·검증·멈춤**을 정한다.
- 에이전트 파일은 **같은 뼈대에 칸만 갈아끼운다.** `model`과 `tools` 두 줄이 급과 권한을 정한다.
- 권한 제한은 **정식 로드돼야** 걸린다. 정의 파일 위치에서 세션을 새로 열 것.
- 오케스트레이터·감독자는 에이전트가 아니라 **스킬을 읽은 메인 세션**이다.
- 판정 에이전트에는 **판정의 뜻이 아니라 순서**를 준다.
- 패턴은 고르는 게 아니라 **Phase마다 조합**한다. 바깥(계층·파이프라인)은 뼈대, 안쪽(팬아웃·생성-검증·감독자)은 엔진.
- **일의 종류가 바뀌면 팀을 바꾸고**, 같은 일이 이어지면 유지한다.
- 대규모 반복 작업은 진행 상태를 **파일 하나**에 둔다. 그래야 끊겨도 이어진다.
