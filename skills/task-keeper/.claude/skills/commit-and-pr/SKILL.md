# Commit and Pull Request Skill

## Goal

현재 변경사항을 커밋하고, 그 브랜치로 Pull Request를 만드는 과정을 한 번에 처리합니다.
커밋 규칙과 PR 규칙은 새로 정하지 않고 기존 두 스킬을 그대로 따릅니다.

- 커밋: `git-commit` 스킬 (`.claude/skills/git-commit/SKILL.md`)
- PR: `create-pr` 스킬 (`.claude/skills/create-pr/SKILL.md`)

## Instructions

1. **상태 확인**
   - `git status`로 변경사항을 확인합니다. 커밋할 변경이 없고 push할 커밋도 없으면 중단하고 알립니다.
   - `git branch --show-current`로 현재 브랜치를 확인합니다.

2. **브랜치 준비**: 현재 브랜치가 기본 브랜치(`main`)이면 커밋 **전에** 새 브랜치를 만듭니다.
   - 변경 내용에 맞는 이름을 제안하고 사용자 승인을 받습니다. 형식은 `<type>/<짧은-설명>`입니다 (예: `fix/tasks-n-plus-one`).
   - `git switch -c <브랜치>`로 만듭니다. 커밋되지 않은 변경은 그대로 따라옵니다.

3. **커밋 범위 결정**: 변경 파일을 성격별로 묶어 보여주고, 무엇을 커밋할지 사용자에게 확인합니다.
   - 이번 작업과 관계없어 보이는 파일이 섞여 있으면 따로 알립니다.
   - 성격이 다른 변경(예: 기능 코드와 문서)은 커밋을 나눕니다.

4. **커밋**: `git-commit` 스킬을 호출하여 그 절차대로 커밋합니다.
   - 3단계에서 정한 파일만 스테이징합니다.
   - git 사용자 정보가 설정되어 있지 않으면 사용자에게 알리고, 어떤 이름과 이메일을 쓸지 받습니다.

5. **PR 생성**: 이어서 `create-pr` 스킬을 호출하여 그 절차대로 push하고 PR을 만듭니다.
   - 이 브랜치에 이미 열린 PR이 있으면(`gh pr view --json url`) 새로 만들지 않습니다. push만 하고, 기존 PR에 커밋이 추가되었다고 알립니다.

6. **결과 보고**: 아래를 한 번에 보여줍니다.
   - 만든 커밋 목록 (해시, 메시지)
   - PR URL과 연결된 이슈
   - 커밋하지 않고 남겨 둔 파일

## Constraints

- 커밋 메시지와 PR 본문의 규칙은 두 스킬을 따릅니다. 이 스킬에서 따로 바꾸지 않습니다.
- 승인 지점은 두 번입니다. 커밋 범위와 메시지를 정할 때, 그리고 PR 내용을 정할 때입니다. 사용자가 "확인 없이 진행"이라고 명시한 경우에만 생략합니다.
- 기본 브랜치(`main`)에 직접 커밋하거나 push하지 않습니다.
- `git push --force`는 사용자가 명시적으로 요청한 경우에만 사용합니다.
- 커밋이 실패하면 PR 단계로 넘어가지 않습니다.
